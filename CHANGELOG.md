# Changelog

All notable changes to TallPBX will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Older releases (1.0.0 through 4.2.1) are archived in [docs/changelog/CHANGELOG-1.x-4.2.x.md](docs/changelog/CHANGELOG-1.x-4.2.x.md).

## [Unreleased]

### Changed
- **Bounded System Journal and FreeSWITCH File Rollover**: TallPBX now installs `/etc/systemd/journald.conf.d/tallpbx.conf` to cap the system journal at 1 GB and 30 days, with journal files rotating at 100 MB and no more than 10 files. FreeSWITCH's internal `freeswitch.log` rollover is reduced from 1 GB × 32 files to 250 MB × 10 files, keeping the two largest log sources bounded without replacing package-provided `logrotate` policies. **Upgrade note**: existing servers can install the journald template and restart `systemd-journald`, then run `sudo bash scripts/resources/freeswitch.sh --configure-only`, `fs_cli -x 'reloadxml'`, and `fs_cli -x 'reload mod_logfile'` to apply the FreeSWITCH limits.
- **Ten-Day Daily Laravel Application Logs**: New installations now log Laravel application activity to dated daily files (`storage/logs/laravel-YYYY-MM-DD.log`) and keep 10 days of history instead of writing one unbounded `laravel.log` through the stack/single channel. The installer, `.env.example`, configuration defaults, environment reference, and log-handling scripts all use this default. **Upgrade note**: installer re-runs preserve custom logging choices and migrate only the previous `LOG_CHANNEL=stack` / `LOG_STACK=single` default to `LOG_CHANNEL=daily` with `LOG_DAILY_DAYS=10`; run `tpbx optimize:clear` after an installer re-run or a manual `.env` change.
- **Firewall Loopback `notrack` and Recommended Pre-Filter Order**: The generated `nftables` ruleset (`table inet tallpbx_filter`) now includes `raw_prerouting` (`iifname "lo" notrack`) and `raw_output` (`oifname "lo" notrack`) chains at priority `raw` (`-300`), preventing local IPC (`mod_xml_curl`, Redis, MariaDB, FreeSWITCH ESL, and Laravel Reverb) from allocating `nf_conntrack` entries or exhausting the 8,192-entry default conntrack table on 1 GB appliances. The default pre-filter order in `PreFilterCompiler` now evaluates small explicit deny sets (`blacklist` and `banned`) *before* `fast_path` (`ct state established,related accept`) so manual blacklists and active bans sever ongoing sessions immediately without relying on conntrack flushing, while keeping large CIDR trees (`threat_feeds` and `geo_perimeter`) *below* `fast_path` so RTP media avoids CIDR tree lookups and outbound return traffic continues to bypass Geo-Blocking in allowlist mode. **Upgrade note**: apply the updated ruleset via the Security Center or `tpbx security:apply`; if you previously saved a custom pre-filter order and want the new recommended order, click **Reset to recommended order** in **Security Center → Firewall Rules**.
- Firewall Observe Mode now tags new kernel log entries with `tpbx-observe:`. The Security Center and `tpbx security:observe` still read entries with the previous prefix. On an existing appliance, install the updated helper with `sudo install -m 0750 -o root -g www-data /var/www/tallpbx/scripts/resources/tallpbx-security /usr/local/sbin/tallpbx-security`, then reapply the rules in the Security Center or run `tpbx security:apply` to start using the new tag.

### Fixed
- **Log Viewer Memory Use and Auto-Refresh Toggle**: Opening a large log file in **Logs** no longer fails with a PHP memory-exhaustion error. The viewer now reads only the most recent matching lines from the end of the file instead of loading the entire file into memory, so memory use stays small regardless of log size; a pathologically long single line is truncated for display rather than buffered whole, and files that have not changed are skipped between auto-refresh ticks. The **Auto-refresh** toggle now actually controls refreshing: when it is off, the page no longer polls in the background.
- **FreeSWITCH Log Rollover Applies Immediately and Ignores Commented Params**: The installer rewrites only active `rollover`/`maximum-rotate` params in `logfile.conf.xml` (a commented-out default no longer suppresses the bound) and reloads `mod_logfile`, so the 250 MB × 10 limit takes effect on fresh installs without a FreeSWITCH restart.
- **Installer Logging Migration Handles Quoted `.env` Values**: Re-running the installer now recognizes `LOG_CHANNEL`/`LOG_STACK` values that are quoted or carry stray whitespace, so the previous `stack`/`single` default is reliably migrated to `daily`.
- **Load-Test Listener Assertions Survive the Midnight Rollover**: The FreeSWITCH listener start-up check now reads every daily `laravel*.log`, so a capacity run that crosses midnight no longer fails because the newest daily file does not yet contain the record.
- **Default Sofia `rtp-timer-name=soft` for Instant Call Hangup**: `DefaultSipProfilesProvisioner` and `SipProfileService::generateConfig()` now emit `<param name="rtp-timer-name" value="soft"/>` when omitted, preventing FreeSWITCH from blocking `BYE` teardown for 5 seconds on muted, one-way, or media-free calls and eliminating repeated `BYE` retransmissions. **Upgrade note**: existing installations pick up the parameter after reloading or restarting Sofia profiles (for example from **SIP Profiles** in the panel, or `fs_cli -x 'sofia profile internal restart'` and `fs_cli -x 'sofia profile external restart'` during a maintenance window).
- **Fresh-Install `mod_json_cdr` Runtime Loading, `vars.xml` Console Loglevel, and Installer Step Counter**: `scripts/resources/freeswitch.sh` now runs `configure_json_cdr` before `configure_dynamic_xml`, restricts `json_cdr.conf.xml` to `0640` (`freeswitch:freeswitch`), and reloads XML and loads/reloads `mod_json_cdr` through `fs_cli` once `FREESWITCH_CDR_TOKEN` is rendered during `--configure-only`, so fresh installs ingest CDRs immediately without needing a post-install FreeSWITCH restart. `configure_freeswitch_switch_defaults()` also synchronizes `console_loglevel` in `vars.xml` with `FS_LOG_LEVEL` (`notice` by default), and `scripts/install.sh` updates `INSTALLER_TOTAL_STEPS` from `6` to `7` so progress output matches all seven `run_step` stages (`[1/7]`–`[7/7]`).
- The load-test harness now preserves failed SIP rungs, verifies the build and generator files, and checks that extended scenarios produced passing verdicts. Both XML handlers must pass a short SIP teardown check before the capacity ladder starts.
- Load tests now measure actual CPU sampling time and verify FreeSWITCH logging after handler switches. The seeder protects existing tenants and removes only optional fixtures it created.
- The installer checks FreeSWITCH's reply when activating `mod_json_cdr` and verifies that the module is loaded before reporting success.

## [5.4.0] - 2026-11-17

### Added
- **Optional MariaDB Storage for FreeSWITCH Runtime Data**: FreeSWITCH can now use a dedicated MariaDB database through native `mod_mariadb` instead of its disk-backed SQLite runtime databases. SQLite remains the default. New installations can select MariaDB with `FSPBX_FREESWITCH_DB_DRIVER=mariadb`; existing appliances must provision the separate database and module, set `FS_DB_DRIVER=mariadb` and the `FS_DB_*` credentials, then reconfigure and restart FreeSWITCH as described in the [operations guide](docs/operations.md#freeswitch-runtime-database-sqlite-default-vs-mariadb). The FreeSWITCH settings cover core, FIFO, Sofia, call-center, and voicemail runtime storage. No Laravel migration is required. Capacity testing of this optional mode remains future work.

### Changed
- GitHub Releases now link to the cumulative release notes and detailed changelog at each release's tag, keeping the release page focused on that version while preserving access to the history available when it shipped.
- Installation, environment, operations, and scaling guides now distinguish the default disk-backed SQLite runtime database from the optional MariaDB mode, make clear that RAM-backed SQLite is a historical benchmark experiment rather than a deployment option, and clarify the Fast/Stock XML-handler switch, its Nginx requirement, and related configuration details.

### Removed
- The completed audit-remediation implementation plan was removed from the live documentation; its contents remain in the v5.3.0 Git history.

## [5.3.0] - 2026-11-16

Closes the audit findings `T01`–`T03`, `C01`–`C05`, `O01`–`O08`, `D01`–`D10`, and `M01`–`M02`. Every correction below came from the plan's own review rounds; the completed implementation plan and its provenance remain available in the v5.3.0 Git history.

### Added
- **Authoritative Restore Journal and Database-Free Status Reader (O02)**: Each privileged restore now records its lifecycle in `/var/lib/tallpbx/restore-journal/` (`0700 root:root`), a directory that survives the database the restore replaces. Entries are written atomically and durably (sync the complete temporary file, rename it, then sync its directory) by the root helper only; the queue worker hands metadata over on the request marker instead. `sudo tallpbx-restore-status` prints one row per operation without booting Laravel, so it works while the database is being replaced. A new `backups:reconcile-restore-journal` command (with a `--operation=` filter) projects the journal back into `restore_operations` after the import, recreating the row and a snapshot of the requester's name and email. **Upgrade note**: a fresh install creates the journal directory; an existing appliance is prepared automatically on the first restore, or in advance with `sudo install -d -m 0700 -o root -g root /var/lib/tallpbx/restore-journal`. Run `tpbx migrate` for the new requester-snapshot columns.
- **Bounded Web-Update Worker Restart (O06)**: `/usr/local/sbin/tallpbx-update-workers` is the only privileged action a web update may take. It accepts no arguments, names its unit allowlist in the script (`freeswitch-listener`, `tallpbx-queue`, `tallpbx-scheduler`, `tallpbx-cdr-worker`, `tallpbx-reverb`, plus an opt-in `tallpbx-xml-worker` only when already active), and refuses to touch MariaDB, Redis, Nginx, FreeSWITCH, or PHP-FPM. `scripts/resources/install-update-workers.sh` installs it root-owned with a `0440` sudoers drop-in that forbids arguments and validates it with `visudo -c -f`; the installer runs it automatically. **Upgrade note**: an existing appliance must run `sudo bash /var/www/tallpbx/scripts/resources/install-update-workers.sh` once after deploying this release, or the web updater refuses to start and reports the same command.
- **Tenant-Relative CDR Direction (C02)**: The CDR list, CSV export, and detail page now show a direction relative to the record's own tenant — `internal`, `inbound`, or `outbound` — derived from the paired leg. A call that leaves one tenant and arrives at another reads as outbound for the caller and inbound for the callee, which a per-leg channel direction cannot express. The stored FreeSWITCH channel direction stays visible on the detail page under its own label. List renders and exports preload peer tenants in batches, so the extra lookup never becomes N+1.
- **Desk-Phone Provisioning Guide, Backup & Restore Journey, Developer Guide, and Release Checklist**: `docs/provisioning-guide.md` documents the supported endpoint, its Basic-auth and CIDR settings, and the `404`/`401`/`403`/`429` failures. `docs/backup-restore-guide.md` documents scope contents, storage and encryption caveats, verification, downtime, the two time bounds, failure recovery, and restoring onto a replacement host. `docs/developer-guide.md` is the developer entry point (setup, module contracts, tenancy, verification). `docs/release-checklist.md` records the tested SHA, commands, environment, and results, and the README now opens with an audience map.

### Changed
- **Restore Request Claiming and Lifecycle (O01, O04)**: `tallpbx-restore-dispatch` no longer aborts the loop on the first stale marker. It takes an exclusive lock, refuses to overlap two restores, claims each request by renaming it, isolates a failing request as `<uuid>.failed`, moves non-UUID markers into `rejected/`, and recovers a claim abandoned by a crashed dispatcher only after the staleness bound. `backups:restore-operation` is idempotent for an operation the journal already finished and refuses to start an unjournalled restore. Restore commands now carry a 15-minute ceiling (`TALLPBX_RESTORE_COMMAND_TIMEOUT`) and the whole operation a 1-hour budget (`TALLPBX_RESTORE_OPERATION_DEADLINE`) that is never reset between phases; the database dump is streamed through a file handle instead of being buffered in memory.
- **Faster, Safer Backup and Restore Files (O03)**: A restore now brings back top-level files in `storage/app` beside the directories it already restored, and the pre-restore snapshot honours the backup's own media exclusions so it does not duplicate the trees it protects. The database dump is written by the client (`--result-file`) instead of being captured on stdout, and the database password never reaches the command line — it is passed through `MYSQL_PWD`.
- **CDR Tenant Attribution (C02)**: A CDR's owner is now decided only from call-time identity — the channel-local `tenant_id` the dialplan stamps on the executing channel, or the tenant context the channel executed — and the two must agree. A domain mapping is diagnostic context, never an ownership source, so a delayed payload can no longer be assigned to whoever owns its former domain. Direct bridge legs carry an explicit destination-owned `[tenant_id=<id>]` block (dialplan bridges, ring groups, follow-me, outbound routes, emergency routes, external destinations, and operator-panel origination), and a leg with no provable owner is quarantined instead of guessed.
- **One Transaction Owner for Extension Saves (C04, M01)**: Saving an extension writes the extension, its portal users, its SIP account, and its voicemail in one transaction through the new `ExtensionSaveService`. A failure in any step now leaves no orphan rows (a provisioned mailbox directory is accepted as an idempotent, owner-scoped side effect). Routing-cache invalidation waits for the commit, so a concurrent FreeSWITCH lookup can no longer repopulate the cache from pre-commit state.
- **Update Targets Resolve to Explicit Refs (O05)**: Selecting a tag now checks it out detached at its commit instead of trying `origin/<tag>`, and an unresolvable target reports `Target not found` instead of a fabricated zero commits behind. The preview, the pipeline, and the rollback all use the same resolution, and a rollback from a detached HEAD detaches back to the original commit rather than moving a branch pointer.
- **Updates Reload Resident Workers and Report Failures (O06)**: A web update now restarts the resident PHP workers and verifies each one is active, appending a `Reconcile services` step (`ok`, `warn` for an optional unit, or `failed`). A required worker that stays down fails the update with an operator-actionable reason instead of reporting success while the old code keeps running. A missing helper is detected before Git, Composer, migrations, or the build run.
- **Rollback Restores the Node Dependency Graph (O07)**: A failed update now runs `npm ci --ignore-scripts` from the restored lockfile before rebuilding assets, so a rollback never ships a bundle built against the failed version's `node_modules`.
- **Tenant Derivation in Every Edit Form (C03)**: `BaseEditComponent` derives `tenantId` from the authorized context for every non-admin actor on mount, on each Livewire request (`hydrate()`), and immediately after a property update (`updated('tenantId')`), covering all 36 edit components rather than one form. A crafted payload can no longer redirect a write or trigger a cross-tenant dropdown load, and a tenant user with no authorized tenant context is refused at the write boundary.
- **Bounded CDR Poison-Record Isolation (O08)**: A record the database rejects on its own merits (SQLSTATE `23000` or class `22`) is isolated and quarantined while its neighbours commit; a transient failure (a lost connection) still re-throws so the whole batch is retried. The spool drain quarantines a rejected file instead of deleting it, and `tenant_id` is now write-once — a replayed payload can never move an existing CDR into another tenant's history.
- **Tests Use Their Own CDR Redis Workspace (T01)**: `phpunit.xml` forces `REDIS_CDR_DB=12` and an empty `REDIS_URL`, so a suite run can no longer write to the appliance's CDR database.
- **Coverage Includes Module Sources (T02)**: The PHPUnit coverage scope now includes `app-modules/*/src` alongside `app`, so the reported number covers the code under test.
- **CI and Release Documentation State Their Real Role (T03)**: `.github/workflows/tests.yml` is described as a manual environment-parity check, not the release gate; local appliance verification is the gate, and `docs/release-checklist.md` records its evidence.
- **Module View-Name Resolution Consolidated (M02)**: `ModuleViewName` is now the single implementation behind `BaseEditComponent` and `BaseListComponent`.
- **Environment Reference, Firewall Guidance, and Load-Testing Documents Corrected (D01, D02, D05, D06)**: `FS_SERVER` is documented as the SIP registrar hostname/IP used by provisioning (with the `APP_URL` fallback labelled as a fallback), `FS_DEFAULT_SIP_REALM` as having no config default, the ACL cache keys as `acl_cache_store`/`acl_cache_ttl`, and provisioning authentication as Basic only. `config/freeswitch.php` strips any scheme from `FS_SERVER`/`APP_URL` so a generated phone template never embeds a URL. Load-generator whitelisting goes through Security Center or `tpbx security:apply` instead of a raw `nft` command, the documented load-test variants and flags now match `matrix.php`, and `load-testing/status.md` and the scaling guide separate current support status from dated history and label `30–60+ CPS` figures as projections.

### Fixed
- **CDR Bridge Attribution After Implementation Audit**: FreeSWITCH now receives tenant identity in a per-leg variable block before each bridge endpoint, as its dial-string grammar requires. Dynamic local-extension calls read the destination account's tenant at call time rather than assuming the caller's context owns it; ring-group members use their own tenant. The CDR parser accepts a stamped callee tenant when FreeSWITCH carries the caller's profile context onto a bridged B-leg, but still quarantines an unstamped leg or conflicting channel context. An unpaired B-leg shows `unknown` direction instead of misreporting an incoming cross-tenant call as outbound. Same-tenant and cross-tenant authenticated calls through the real local-extension route verified both CDR legs and their tenant-relative directions on the test host. No migration or `.env` change is required; restart the XML and CDR workers after deployment.
- **Restore Durability and Deadline Backstops**: Journal writes now handle short writes and refuse failed flush/file/directory syncs. Restore subprocesses use the remaining operation budget as well as the 15-minute per-command ceiling, and the systemd restore unit hard-stops blocked file work after one hour. Fresh-install restore preflight checks free space on the nearest existing parent when a backup or media directory has not been created yet. **Upgrade note**: reinstall the updated `tallpbx-restore@.service` unit from `scripts/resources/tallpbx-restore.service` and reload systemd before relying on the new hard stop; no migration or `.env` change is required.
- **Optional XML Worker No Longer Fails an Otherwise Healthy Web Update**: A failed optional XML worker restart now appears as a warning while required worker failures still fail the update. A missing or malformed worker-helper response also fails closed, even if old workers remain active. Reinstall `tallpbx-update-workers` from `scripts/resources/install-update-workers.sh` to deploy the corrected helper on existing appliances.
- **Disabled Accounts Fail Closed (C01)**: A disabled administrator or tenant user is rejected on page requests, Livewire updates, and every Gate/Policy check. An administrator disabled mid-impersonation ends the session instead of continuing as the target, and a disabled target ends only the impersonation. Disabling an account rotates its `remember_token`, so a remember-me cookie issued while it was enabled can no longer restore access.
- **SIP Account and Voicemail Forms Match the Documented Behaviour (D03)**: The concept guide no longer claims credentials are generated automatically; the extension form asks for the SIP password and creates the account only when one is supplied, and a routing-only extension deliberately has none.
- **Loaded Source Links, Module Conventions, and Link Integrity (D07, D10)**: The architecture links point at `app-modules/security/src/Services/Firewall/`, the skill's relative links resolve from its own directory, archived docs are labelled, and a link check over `README.md`, `CHANGELOG.md`, `docs/` and `.agents/` reports no missing relative target. The module-development prose now states that every built-in module declares an explicit `routes/web.php` (enforced by `ModuleArchitectureTest`) and documents the real translation contract (`translationPath()`/`hasTranslations()`), with a scaffold test that pins both the custom-module scaffold and the built-in rule.
- **Restore Fits on Disk Before Anything Is Extracted (O04 follow-up)**: A restore now refuses to start when the archive's uncompressed working set plus a reserve (`max(2 GB, 10 %)`) does not fit on every filesystem it writes to. The check runs after the archive-safety check so an unsafe archive still reports its precise error.
- **Restore Fails When Services Do Not Return (O06)**: A restore now restarts and verifies the required services, probes the database, Redis, and FreeSWITCH, and leaves the appliance in maintenance mode when any required check fails. A half-restored runtime never takes live traffic, and the failure is recorded in the journal with `maintenance_locked: true`.
- **Direct Archive Uploads Respect the 2 GB Ceiling (O04 follow-up)**: An uploaded restore archive is capped at 2,000,000,000 bytes in the application, with matching PHP (`upload_max_filesize`/`post_max_size`) and Nginx (`client_max_body_size`) transport headroom, and the dialog states the limit.
- **Load-Test Seed Command Uses the Configured Realm (D05)**: `pbx:load-test:seed` no longer defaults `--domain` to `load.test.local`; it falls back to `FS_DEFAULT_SIP_REALM` and fails loudly when neither exists, and `pbx-sipp-validate.sh` omits the flag when no realm is chosen.

## [5.2.0] - 2026-11-12

### Added
- **PHP-FPM Worker Ceiling Override**: `PHP_FPM_MAX_CHILDREN` in `.env` pins the PHP-FPM worker ceiling instead of deriving it from detected RAM. It exists for one situation: reproducing a published benchmark tier on hardware of a different size — for example, running the 1 vCPU / 1 GB configuration on a 4 GB test host. Left unset, the ceiling follows memory exactly as before (3 workers on 1 GB, 6 on 2 GB, 12 on 4 GB+). Both the installer and `appliance:sync-host` honour the key, and a value that is not a positive whole number is reported and ignored rather than taking the pool down to zero workers. No migration, FreeSWITCH reload, or other `.env` change is required.
- **GitHub Releases Automation and Cumulative RELEASE-NOTES.md**: Every pushed `vX.Y.Z` tag now becomes a GitHub Release automatically; `.github/workflows/release.yml` extracts the tag's section from the new `RELEASE-NOTES.md` — the cumulative, plain-language summary, newest first, starting at v5.0.0 — and publishes it as the release body. `scripts/release-notes.sh` refuses a tag that is missing from either `RELEASE-NOTES.md` or a dated `CHANGELOG.md` section, so the two files cannot drift apart on a published release. `CHANGELOG.md` history older than 4.3.0 moved to `docs/changelog/CHANGELOG-1.x-4.2.x.md` with a pointer left behind. No application code, migration, or `.env` change is involved.

### Changed
- **Benchmark Cells Now Apply the Shipped Worker-Recycling Bound**: `load-testing/scripts/lib/switch.sh` applied five of the six shipped PHP-FPM directives and left `pm.max_requests` at whatever the host happened to have, so a cell labelled "shipped default" could measure a different configuration than it claimed. A dynamic profile now writes and asserts `pm.max_requests = 10000` alongside the mode, ceiling and idle floor, and the skip check compares it so a stale value is not mistaken for an applied one. `static` cells are unchanged. The harness stays deliberately independent of `scripts/resources/php-fpm-pool.sh`, and both files now record why: the reconciler owns the single shipped shape, while the harness writes disposable per-cell profiles against staged remote checkouts that may predate it.
- **`appliance:sync-host` Reconciles the Whole PHP-FPM Pool**: The command now applies all six pool directives (`pm`, `max_children`, `start_servers`, `min_spare_servers`, `max_spare_servers`, `max_requests`) through `scripts/resources/php-fpm-pool.sh` — the same script the installer runs — instead of rewriting `pm.max_children` on its own. A snapshot restored onto differently sized hardware therefore comes back with a pool that matches that machine, and a fresh install and a restore can no longer produce different shapes from the same documented configuration. The reload now follows the PHP version found in the pool path instead of assuming PHP 8.5.
- **Composer Dependencies Refreshed**: `composer update` brought every dependency to its latest stable release within the existing constraints (424 lock changes); the platform remains PHP 8.5 (8.5.12). Caches were cleared and the Octane and queue workers were reloaded onto the new code; no application code changed.
- **RoadRunner Worker Binary Moved to v3**: Octane 2.23 fixed the version-check incompatibility with RoadRunner 3.0, so the optional XML worker's RoadRunner binary moves from the 2024 calendar-versioned line (2024.3.5) to **3.0.1**. `scripts/resources/freeswitch.sh` now fetches the `3.*` line, replaces a detected 2024 binary on re-run, and closes stdin so the downloader's confirmation prompt can never hang an unattended install (the prompt is what made `rr get` stall; a direct release download is the documented fallback). `SystemdWorkerConfigTest` follows the new pin, and `SddLedgerHygieneTest` now treats a fully archived ledger — every workspace progress file and the index deleted under the completed-task cleanup convention — as the convention's completed state instead of requiring the local index to exist. The running worker was restarted onto the new binary and the Octane parity and tenant-isolation suites pass against it. No migration or `.env` change is required.

### Fixed
- **PHP-FPM Pool Reconciliation Reported Success While Failing**: `appliance:sync-host` previously skipped unwritable pool files, unmatched directives, and failed `systemctl` calls in silence, so an operator saw a green tick whether the pool had been rewritten or not. It now validates the rewritten file with `php-fpm -t`, restores the previous file when the test rejects it, reports the outcome per PHP version, and exits non-zero when the pool could not be brought to the target shape.
- **`.env` Kept Its Group When the Installer Rewrote a Value**: `set_env_value` replaces `.env` through a temporary file and copied only the permission bits, so the replacement belonged to `root:root` instead of `root:www-data`. PHP-FPM reads `.env` as `www-data`, so writing a value outside a full install — or after the final permission repair — left the panel unable to read its own configuration until the next `tpbx permissions:repair`. The helper now copies the owner and group alongside the mode. Installer runs were unaffected because they end with a full permission repair.

## [5.1.1] - 2026-11-09

### Added
- **CDR Health Check and Fallback Counter**: The ingestion path fails soft at every layer, which is right but hides a broken path behind a normal-looking 200. `tpbx cdr:health` — scheduled every five minutes — reports `spooled_posts`, `backlog`, and `failed_posts` as one line each and exits non-zero when any crosses its threshold, so a silent failure appears in the scheduler log. Separately, every fast-entry fail-open now appends one line to `storage/logs/cdr-fast-fallback.log`, which makes a long-running fallback countable instead of invisible. No migration, `.env`, service, or FreeSWITCH change is required.

### Changed
- **PHP-FPM Pool Default Is Now Dynamic With a Measured Ceiling**: The installer configures `pm = dynamic` with one resident worker (`start_servers = 1`, `min_spare_servers = 1`, `max_spare_servers = 2`) instead of five static workers, and derives the ceiling from detected memory: 3 workers on 1GB systems, 6 on 2GB, 12 on 4GB+. The migration refuses to continue if any record already carries a blank reference number, because such a record can never be deduplicated and clearing it is an operator's decision; it never removes call history on its own.
- **FreeSWITCH Dashboard Active Call Refresh on Hangup & Periodic Keepalive**: Resolved a gap where active call counts on the dashboard failed to decrement when calls ended under the default essential ESL profile by registering `ChannelHangupComplete` in `BroadcastDashboardStatsOnFreeSwitchEvent`, and restored the 20-second `HEARTBEAT` keepalive to the essential event profile to preserve self-healing updates for wire:poll-free views.
- **FreeSWITCH Listen Command CLI Option Shadowing**: Removed the legacy closure wrapper in `routes/console.php` that shadowed `FreeSwitchListenCommand` in Artisan, restoring full option descriptions (`--once`, `--timeout`, `--buffer-size`, `--profile`, `--events`) on `--help`.
- **Cached Tenant Identity Can No Longer Outlive an Ownership Change**: The directory lookup caches the answer to "which tenant owns this username". That answer had a 60-second lifetime but no revision, so a SIP account or tenant domain moved to another tenant could keep resolving to the previous tenant until the entry expired. The identity key now embeds an identity epoch — the existing global routing revision — which `RoutingCacheObserver` bumps on every SIP account and tenant domain write (a missing epoch is a miss, never a default). Because the global revision also salts dialplan cache keys, a SIP account or domain edit invalidates each tenant's dialplan once on its next request.
- **Appliance Host Sync No Longer Empties Every Redis Database**: `appliance:sync-host`, which runs after a snapshot restore or an IP or hostname change, called `Redis::flushall()` and therefore wiped all logical databases at once — cache, sessions, and the CDR stream. Only the cache holds rendered routing XML that embeds the old address, and only the cache is safe to discard, so the command now flushes the telephony cache store alone. Signed-in administrators stay signed in, and no call records can be lost to a host sync.

### Removed
- **Lua XML Cache Proxy (Evaluated and Retired)**: The optional in-process FreeSWITCH Lua directory cache is removed from the product after measurement showed the trimmed fast controller and the optional Octane worker deliver comparable call capacity without a mirrored second representation of every rendered document. Removed: the `mod_lua` handler and its `lua.conf.xml` bindings template, the installer's Lua deployment step and `mod_lua` module ordering, the Laravel mirror (`FsXmlMirrorWriter` and the builder hooks), the `freeswitch.lua_proxy` config block, the `FS_LUA_PROXY_*`/`FS_REDIS_*` environment entries, and their test suites. The `freeswitch-mod-hiredis` package, its `hiredis.conf.xml` profile, and the opt-in `FS_HIREDIS_*` tenant-limit and last-call-marker dialplan actions remain in place unchanged. Its measurements remain under `load-testing/results/` and in `docs/load-testing-results.md`, the load-testing matrix drops the `v-lua-*` variants, and the design is recorded in `docs/architecture.md`. The code remains available in the repository history. **Upgrade note**: remove `FS_LUA_PROXY_*` and `FS_REDIS_*` lines from `.env`; delete `/etc/freeswitch/scripts/tallpbx_xml_handler.lua` and `/etc/freeswitch/autoload_configs/lua.conf.xml` if present, comment the `mod_lua` line in `modules.conf.xml`, keep `autoload_configs/hiredis.conf.xml`, and run `tpbx optimize:clear`.
