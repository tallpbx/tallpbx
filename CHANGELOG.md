## [5.2.0] - 2026-11-12

### Added
- **PHP-FPM Worker Ceiling Override**: `PHP_FPM_MAX_CHILDREN` in `.env` pins the PHP-FPM worker ceiling instead of deriving it from detected RAM. It exists for one situation: reproducing a published benchmark tier on hardware of a different size — for example, running the 1 vCPU / 1 GB configuration on a 4 GB test host. Left unset, the ceiling follows memory exactly as before (3 workers on 1 GB, 6 on 2 GB, 12 on 4 GB+). Both the installer and `appliance:sync-host` honour the key, and a value that is not a positive whole number is reported and ignored rather than taking the pool down to zero workers. No migration, FreeSWITCH reload, or other `.env` change is required.
- **GitHub Releases Automation and Cumulative RELEASE-NOTES.md**: Every pushed `vX.Y.Z` tag now becomes a GitHub Release automatically; `.github/workflows/release.yml` extracts the tag's section from the new `RELEASE-NOTES.md` — the cumulative, plain-language summary, newest first, starting at v5.0.0 — and publishes it as the release body. `scripts/release-notes.sh` refuses a tag that is missing from either `RELEASE-NOTES.md` or a dated `CHANGELOG.md` section, so the two files cannot drift apart on a published release. `CHANGELOG.md` history older than 4.3.0 moved to `docs/changelog/CHANGELOG-1.x-4.2.x.md` with a pointer left behind. No application code, migration, or `.env` change is involved.

### Changed
- **Benchmark Cells Now Apply the Shipped Worker-Recycling Bound**: `load-testing/scripts/lib/switch.sh` applied five of the six shipped PHP-FPM directives and left `pm.max_requests` at whatever the host happened to have, so a cell labelled "shipped default" could measure a different configuration than it claimed. A dynamic profile now writes and asserts `pm.max_requests = 10000` alongside the mode, ceiling and idle floor, and the skip check compares it so a stale value is not mistaken for an applied one. `static` cells are unchanged. The harness stays deliberately independent of `scripts/resources/php-fpm-pool.sh`, and both files now record why: the reconciler owns the single shipped shape, while the harness writes disposable per-cell profiles against staged remote checkouts that may predate it.
- **`appliance:sync-host` Reconciles the Whole PHP-FPM Pool**: The command now applies all six pool directives (`pm`, `max_children`, `start_servers`, `min_spare_servers`, `max_spare_servers`, `max_requests`) through `scripts/resources/php-fpm-pool.sh` — the same script the installer runs — instead of rewriting `pm.max_children` on its own. A snapshot restored onto differently sized hardware therefore comes back with a pool that matches that machine, and a fresh install and a restore can no longer produce different shapes from the same documented configuration. The reload now follows the PHP version found in the pool path instead of assuming PHP 8.5.
- **Composer Dependencies Refreshed**: `composer update` brought every dependency to its latest stable release within the existing constraints (424 lock changes); the platform remains PHP 8.5 (8.5.12). Caches were cleared and the Octane and queue workers were reloaded onto the new code; no application code changed.
- **RoadRunner Worker Binary Moved to v3**: Octane 2.23 fixed the version-check incompatibility with RoadRunner 3.0, so the optional XML worker's RoadRunner binary moves from the 2024 calendar-versioned line (2024.3.5) to **3.0.1**. `scripts/resources/freeswitch.sh` now fetches the `3.*` line, replaces a detected 2024 binary on re-run, and closes stdin so the downloader's confirmation prompt can never hang an unattended install (the prompt is what made `rr get` stall; a direct release download is the documented fallback). `SystemdWorkerConfigTest` follows the new pin, and `SddLedgerHygieneTest` now treats a fully archived ledger — every workspace progress file and the index deleted under the completed-task cleanup convention — as the convention's completed state instead of requiring the local index to exist. The running worker was restarted onto the new binary and the Octane parity and tenant-isolation suites pass against it. No migration or `.env` change is required.

### Fixed
- **PHP-FPM Pool Reconciliation Reported Success While Failing**: `appliance:sync-host` previously skipped unwritable pool files, unmatched directives, and failed `systemctl` calls in silence, so an operator saw a green tick whether the pool had been rewritten or not. It now validates the rewritten file with `php-fpm -t`, restores the previous file when the test rejects it, reports the outcome per PHP version, and exits non-zero when the pool could not be brought to the target shape.
- **`.env` Kept Its Group When the Installer Rewrote a Value**: `set_env_value` replaces `.env` through a temporary file and copied only the permission bits, so the replacement belonged to `root:root` instead of `root:www-data`. PHP-FPM reads `.env` as `www-data`, so writing a value outside a full install — or after the final permission repair — left the panel unable to read its own configuration until the next `tpbx permissions:repair`. The helper now copies the owner and group alongside the mode. Installer runs were unaffected because they end with a full permission repair.

## [5.1.1] - 2026-11-09

### Added
- **CDR Health Check and Fallback Counter**: The ingestion path fails soft at every layer, which is right but hides a broken path behind a normal-looking 200. `tpbx cdr:health` — scheduled every five minutes — reports `spooled_posts`, `backlog`, and `failed_posts` as one line each and exits non-zero when any crosses its threshold, so a silent failure appears in the scheduler log. Separately, every fast-entry fail-open now appends one line to `storage/logs/cdr-fast-fallback.log`, which makes a long-running fallback countable instead of invisible. No migration, `.env`, service, or FreeSWITCH change is required.

### Changed
- **PHP-FPM Pool Default Is Now Dynamic With a Measured Ceiling**: The installer configures `pm = dynamic` with one resident worker (`start_servers = 1`, `min_spare_servers = 1`, `max_spare_servers = 2`) instead of five static workers, and derives the ceiling from detected memory: 3 workers on 1GB systems, 6 on 2GB, 12 on 4GB+. The 2026-11-08 worker sweep on the minimal tier (recorded in [load-testing-results.md](docs/load-testing-results.md) → *PHP-FPM Static Worker Sweep on Minimal Hardware*) measured every pool size from 5 down to 1: at the supported rate of 5 calls/sec every size completed 300/300 calls, and at the 6 calls/sec boundary fewer workers completed *more* calls (38 % at 5 workers versus 84 % at 1) because extra workers only deepen the request backlog against the 2-second nginx read timeout in front of PHP-FPM. `pm.max_requests = 10000` is now set so long-lived workers recycle instead of accumulating memory over weeks of uptime. Minimal hardware idles at ~24 MB of PHP-FPM instead of ~83 MB. The measurement was repeated on 2 vCPU / 2 GB on 2026-11-09: the shipped pool completed 600/600 calls at 10 calls/sec and lost 58 % at 12 calls/sec, and the pool shape proved second-order there — five shapes landed within 34–44 % at that boundary — so the ceiling follows detected memory rather than being trimmed further on multi-core hosts. **Supported rates with the shipped default are 5 calls/sec on 1 vCPU and 10 calls/sec on 2 vCPU.** **Upgrade note**: existing installs keep their pool file until the installer (or `bash scripts/resources/php.sh`) is re-run and PHP-FPM is restarted; no migration, `.env`, or FreeSWITCH change is required.
- **Agent Instructions, IDE Rules, and Project Skills Alignment**: Aligned `AGENTS.md`, `.cursorrules`, `.github/copilot-instructions.md`, `CLAUDE.md`, and all project skills (`tallpbx-custom`, `freeswitch-development`, `testing-best-practices`, `livewire-development`) with 5.x conventions, enforcing the 5-step verification gate and appliance CLI (`tpbx`).

### Fixed
- **Let's Encrypt Port-80 Loopback Vhost & FreeSWITCH Source `mod_json_cdr` Parity**: Added missing server-level `root /var/www/tallpbx/public;`, unescaped `${php_version:-8.5}` PHP-FPM socket paths, and `HTTP_AUTHORIZATION` FastCGI header forwarding in `scripts/resources/letsencrypt.sh`, and guarded `freeswitch-mod-json-cdr` apt installation on source builds while enabling `event_handlers/mod_json_cdr` in `enable_tallpbx_source_modules()`.
- **Load-Testing Harness Staging & Pool-Scoped Artifact Paths**: Fixed remote SIPp scenario and validation script staging paths in `sipp_prepare_generator()`, unified `variant_dir` resolution across `run_sip_phase`, `run_ablation_phase`, and `run_sip_smoke`, added `FS_ESL_EVENT_PROFILE` and `FS_BROADCAST_THROTTLE_MS` to `snapshot_env` / `restore_baseline`, and replaced hardcoded driver host addresses with environment variables.

## [5.1.0] - 2026-11-08

### Added
- **Fast CDR Ingestion Entry**: CDR posts no longer boot the full application. `POST /api/v1/cdr` is now served by `public/cdr-fast.php` through a shared minimal bootstrap (`App\Support\MinimalBootstrap`, `App\Support\CdrFastBootstrap`) that registers five service providers instead of roughly ninety — no database, encryption, view or module providers, because the endpoint only verifies the token and appends to the Redis stream. The controller returns `JsonResponse` directly so the `response()` helper cannot pull the view factory back in. Both nginx templates point the location at the new entry, forward the `Authorization` header and ship the stock block commented underneath, so rollback is a copy and `systemctl reload nginx`; there is no FreeSWITCH, database, or stream-format change. The entry fails open to `index.php`, so a fault costs speed and never a record. The XML fast entry was refactored onto the same shared bootstrap with no behaviour change, guarded by its existing byte-equality suites. **Upgrade note**: re-run `bash scripts/resources/nginx.sh` (or the installer) to deploy the new location, then `tpbx optimize:clear`.

### Changed
- **CDR Performance Plan Retired After Delivery**: Removed `docs/cdr-performance-improvement-implementation-plan.md` now that its implementation and measurement are complete. Every TDD step shipped: the shared minimal bootstrap, `CdrFastBootstrap`, `public/cdr-fast.php`, the `JsonResponse` controller change, the nginx locations in both templates, and the XML fast entry refactor. The measured outcome is recorded in [`load-testing/status.md`](load-testing/status.md): 5 CPS serves 300/300 calls with 601 CDR rows against 276/300 and 46/552 before the change. The plan remains recoverable from git history. No migration, `.env`, service, or FreeSWITCH change is required.
- **CDR Pipeline Plan Retired After Completion**: Removed `docs/superpowers/plans/2026-10-31-cdr-modernization-pipeline.md` now that every task in it has shipped. The pipeline's architecture and durability rules are documented in [`docs/architecture.md`](docs/architecture.md) §17, with operating instructions in [`docs/operations.md`](docs/operations.md) → Call Detail Records (CDR) Pipeline; the plan itself remains recoverable from git history. No migration, `.env`, service, or FreeSWITCH change is required.

### Fixed
- **Fast Entry Fail-Open Restored**: The fast front controllers answer a fault by re-serving the request through `index.php`, but `public/index.php` loaded `bootstrap/app.php` with `require_once`, which returns `true` once the fast entry has already included that file in the same process — so the fallback died with a fatal error instead of serving the request. `index.php` now re-evaluates the bootstrap file, so a fault costs speed and never a record. This covers `public/cdr-fast.php` and the existing `public/xml-handler-fast.php`. No migration, `.env`, or FreeSWITCH change is required.

- **Refuse XML Bindings That Crash FreeSWITCH**: `mod_xml_curl` registers every `<binding>` in `xml_curl.conf.xml` even when it has no `gateway-url`. Such a binding reaches the module with a null url, and the first directory or dialplan lookup passes NULL to `strstr()` and kills the switch with a SIGSEGV. A new `App\Support\FreeSwitchXmlCurlConfig` validator and the `freeswitch:validate-xml-curl` command detect this, and the installer now refuses to finish writing the configuration when any binding lacks a usable `gateway-url`. Commented-out bindings are ignored, so the disabled-state files remain valid. No migration or `.env` change is required.

## [5.0.0] - 2026-11-05

### Added
- **Load-Test Refresh Harness**: Added the tooling the two-stage capacity refresh needs to stay reproducible. A declarative matrix (`load-testing/matrix.php`) lists every hardware tier, XML-serving variant, load profile, cache policy and SIPp scenario; `tpbx pbx:load-test:manifest` writes a machine-readable snapshot next to each run (build SHA, host sizing, PHP-FPM pool, FreeSWITCH runtime database mode, cache TTLs, firewall state, and a redacted `.env`); `load-testing/scripts/lib/switch.sh` applies each configuration switch and then reads the value back, so a setting that silently did not take effect aborts one measurement cell instead of producing a plausible but meaningless number; and `load-testing/scripts/load-test-matrix.sh` lists, dry-runs and executes the cells, restoring the documented baseline from a teardown trap. Measurement still runs through the existing `pbx:load-test:seed`, `pbx:load-test:dialplan` and `load-testing/scripts/pbx-sipp-validate.sh`, so results stay comparable with earlier series. No migration, service, or `.env` change is required.
- **Reverb Telephony Broadcast Debouncing & Rate Limiting**: Added in-memory rate limiting and debouncing for real-time WebSocket events (`DashboardStatsUpdated` and `TelephonyUpdated`) in `BroadcastDashboardStatsOnFreeSwitchEvent` and `BroadcastTelephonyOnFreeSwitchEvent`. Configured via `FS_BROADCAST_THROTTLE_MS` (default: 500 ms) in `config/freeswitch.php`, `.env`, and `.env.example`. Prevents synchronous HTTP POST flooding to Reverb on port 8080 during call bursts and stops connected browser Livewire components from generating cascading FreeSWITCH ESL queries (`show channels as json`).
- **Telephony Capacity Scaling Guide & Architectural Roadmap**: Authored [`docs/telephony-capacity-scaling-guide.md`](docs/telephony-capacity-scaling-guide.md), documenting empirical findings from server-to-server SIPp capacity testing on 1 vCPU cloud hosts, identifying the 10 CPS CPU saturation boundary (33% ESL event parsing, 33% FreeSWITCH SIP/RTP, 25% Reverb WebSockets, 8–16% kernel interrupts), establishing why static XML files do not solve the hardware bottleneck, and laying out a 5-phase optimization roadmap and hardware progression matrix to scale call capacity up to 60–80+ CPS.
- **Head-to-Head Call Capacity Benchmark Comparison**: Recorded end-to-end SIP call capacity results in [load-testing results](docs/load-testing-results.md#cross-architecture-call-capacity-octane-vs-lua-vs-fast-controller) across four architectures (Octane Lean Worker at 6.23 sustained CPS / 99.3% completion, Lua Proxy alone at 4.60 CPS, Fast Controller + Lua Proxy at 3.30 CPS, and Fast Controller alone stalling under dynamic PHP-FPM pools). Explains why Octane's failure domain isolation on port 8090 prevents administrative panel HTTP 504 timeouts and eliminates audible dead-air call setup delay.
- **Persistent RoadRunner Octane Lean XML Worker Service (Opt-In Performance Mode)**: Deployed an opt-in resident telephony XML worker listening on `127.0.0.1:8090` managed via `tallpbx-xml-worker.service` (installed disabled by default). Powered by RoadRunner via Laravel Octane 2.x, the worker acts as the primary tier on the 3-tier `xml_curl.conf.xml` binding ladder (`tallpbx-octane` → `tallpbx-fallback` → `tallpbx-stock`). It boots with `TALLPBX_WORKER_ROLE=telephony` and registers a stripped allowlist of 24 telephony module providers plus the core framework providers it needs (`TelephonyWorkerProviders`), bypassing the administrative panel modules, Livewire, and session overhead. The worker uses Redis atomic locks to prevent cache stampedes, queries MariaDB with persistent PDO connections, and deterministically resets tenant identity via `ClearTenantContext` and `VerifyCleanDatabaseState` after each request to guarantee complete cross-tenant isolation.
- **CDR Panel: Leg Filtering, Recording Playback, and Raw Diagnostics**: The call detail list can filter by call side (All / A-leg / B-leg), shows each record's leg as a monospace badge, offers a playback shortcut for recorded calls, and pages through history with a load-more control so the table no longer grows with every call the worker stores. The detail page gains an audio player, a collapsible "Raw Technical Diagnostics (JSON)" view of the untouched payload, and the linked-leg reference. Recording playback runs through a new secure streaming route that re-applies tenant scope and refuses any stored path that does not resolve inside the configured recording roots — path traversal and cross-tenant access both answer 404. Translation keys are parity-complete across English, Spanish, and French.
- **CDR Worker Supervision and Spool Reconciliation**: The CDR pipeline now runs unattended. `tallpbx-cdr-worker.service` (installed and enabled by the installer alongside the queue and scheduler services) supervises `tpbx cdr:work` as `www-data` with `NoNewPrivileges`, a strict filesystem sandbox, and automatic restarts. `tpbx cdr:drain-spool` reconciles the failure spool — deliveries that exhausted their retries — through the same parser and transactional writer as the live stream, removing each file only after its row is committed or its payload is quarantined; it runs every five minutes from the scheduler. The scheduler's sandbox now whitelists `/var/log/freeswitch/json_cdr`, without which the scheduled drain would appear healthy while files piled up. **Upgrade note**: run the installer (or copy `scripts/tallpbx-cdr-worker.service` to `/etc/systemd/system/`, then `systemctl daemon-reload && systemctl enable --now tallpbx-cdr-worker`) and restart `tallpbx-scheduler` to pick up the new sandbox paths.
- **CDR Digestion Worker (`tpbx cdr:work`)**: The durable half of the pipeline is in place. Buffered call records are parsed, committed to MariaDB in one transaction per batch, and removed from the Redis stream only after that commit — a crash at any point replays entries instead of losing them. Records are keyed by `(call_uuid, leg)` so replays update instead of duplicating, both call legs are stored and cross-linked through `b_leg_uuid`, and every row carries an explicit ordered UUID. Payloads that cannot be parsed, lack a call uuid, or belong to a domain no tenant owns are quarantined to `/var/log/freeswitch/json_cdr/quarantine/` for review instead of being dropped or guessed at. The field mapping is verified against real payloads captured from a bridged call on the reference host (kept as test fixtures), and a digest lock keeps concurrent workers from racing. The command supports `--once` for health checks and warns when the stream backlog grows past the configured threshold (1,000 by default).
- **CDR Ingestion Endpoint (`POST /api/v1/cdr`)**: mod_json_cdr's call records now land in the application instead of 404ing. The endpoint verifies the per-install token in constant time (Basic `tallpbx:<token>` credentials, Bearer header, or query string, failing closed while the secret is unconfigured), appends the untouched JSON document to the isolated Redis stream on database 3 (`pbx:cdr:stream`, via an unprefixed connection so operational tooling sees the literal key), and answers an empty 200 with no database work on the request path. A buffer outage answers 503 so FreeSWITCH retries and then spools the record to its error directory — nothing is silently dropped. Rate limiting uses a dedicated env-configurable limiter (`FREESWITCH_CDR_THROTTLE_*`) defaulting to 6,000 requests per minute per IP, matching the xml-handler ceiling since two call legs double the post rate. **Upgrade note**: run `tpbx optimize:clear`; on existing installs add `REDIS_CDR_DB=3` to `.env` (the token is provisioned by the installer's TALL step).
- **FreeSWITCH JSON CDR Gateway Provisioning**: The installer now deploys `mod_json_cdr` end to end: the `freeswitch-mod-json-cdr` package, a versioned `json_cdr.conf.xml` template, the failure spool directories, and the module loader line. The template posts one raw JSON document per call leg to `http://127.0.0.1/api/v1/cdr` with `encode=false` and `encode-values=false`, records both legs, and — because it sets no `log-dir` — only deliveries that exhaust their retries touch disk (in `/var/log/freeswitch/json_cdr/failed`, group-writable so a future drain command running as `www-data` can reconcile them). The shared secret is generated per install (`FREESWITCH_CDR_TOKEN`, provisioned like `FS_XML_HANDLER_TOKEN`) and injected into the deployed file by a helper that refuses to render on an empty token, so the repository never carries a credential. nginx now forwards `HTTP_AUTHORIZATION` to PHP-FPM so the Basic auth handshake reaches the application. **Note**: call records begin spooling only once the ingestion endpoint ships; failed posts land in the spool directory by design.
- **CDR Redis Durability Baseline**: The installer now enables Redis append-only persistence (`appendonly yes`, `appendfsync everysec`) and sets `vm.overcommit_memory = 1` before restarting Redis, then checks the running host and warns when either setting is inactive. Undigested call records held in the CDR stream now survive a restart, and a failed snapshot no longer turns into a total write refusal that breaks panel sessions and cache writes. The settings are written through `scripts/resources/redis-durability.sh`, which is covered by fixture tests.
- **Optional Lua XML Cache Proxy (Default Off)**: FreeSWITCH can now answer directory and dialplan lookups from Redis inside the switch, before `mod_xml_curl` reaches PHP. Laravel mirrors each rendered document into Redis DB 0 under the `pbx:fsxml` namespace through an unprefixed connection, and embeds the routing revisions in every payload key so a panel change invalidates the next lookup immediately. Dialplan is the path that runs on every call leg; its key carries both the tenant revision and the identity epoch, and the tenant travels inside the context name, so a stale document can never route a live call with superseded rules. A small Lua handler performs three or four `GET`s and returns nothing on any doubt, so FreeSWITCH falls back to the unchanged PHP path. Configuration, phrase, and ACL lookups are not proxied. The feature ships disabled (`FS_LUA_PROXY_ENABLED=false`); `scripts/resources/freeswitch.sh` deploys the handler, the bindings template, and the tuned hiredis profile on every install or configure run, keeps `mod_lua` ahead of `mod_xml_curl`, and preserves an operator-supplied Redis password — but never enables the feature. Enabling is `FS_LUA_PROXY_ENABLED=true` plus a FreeSWITCH restart; rollback is removing the bindings, with no database, `.env`, or PHP change required. See `docs/operations.md` → Optional Lua XML Cache.
- **Fast XML Handler Default Entry Point**: The FreeSWITCH XML handler now runs through a minimal bootstrap (`public/xml-handler-fast.php`, backed by `App\Support\XmlHandlerFastBootstrap`) as the shipped default on `127.0.0.1:80/api/v1/xml-handler`. It registers 32 service providers: 8 framework providers in `FRAMEWORK_PROVIDERS` + 24 telephony module providers in `freeswitch.xml_module_providers` after trimming `TranslationServiceProvider` and `LivewireServiceProvider`, rather than roughly 90 full application providers. Measured on the 1 vCPU reference host: 12 ms less work per lookup, latency down about 30 %, and 45–50 % more throughput, with byte-identical XML. Any error in the fast path falls back to the full application (`index.php`), so a fault costs speed rather than registrations. Rollback is a single nginx location block; no database, `.env`, or FreeSWITCH change is required.
- **5.x Major Release Series Kickoff**: Created the `5.x` series branch (`5.x`) for next-generation telecommunications features and high-throughput architectural enhancements, starting with the Pulse-style Redis Stream CDR Ingestion Pipeline and Version-Aware Lua Redis Proxy.
- **Architectural Implementation Plans**: Created the implementation blueprint for the high-concurrency Redis Stream CDR buffer (the pipeline plan) and an initial Lua Redis proxy draft. The first-draft proxy (superseded before implementation) and the static architectural review were removed once their findings were implemented and folded into [docs/architecture.md](docs/architecture.md); recover them from git history if needed.

### Changed
- **Fast Controller Default with the Octane Worker as an Opt-In Performance Mode**: Fresh installs now serve FreeSWITCH XML through the trimmed fast controller (both the HTTP and the Let's Encrypt nginx templates), which also ships as a commented rollback block so the stock full-application mode stays one copy-and-reload away. The installer installs the Octane RoadRunner worker unit **disabled** instead of enabling and starting it, and writes the three `mod_xml_curl` bindings that form the XML ladder: the optional worker first (1 s timeout), the fast controller behind nginx (2 s), then a logged stock location that forwards to the full application (3 s). FreeSWITCH re-sends the complete POST request to each binding, so lookup fields survive every fall-through; enabling the worker is a single `sudo systemctl enable --now tallpbx-xml-worker` with no FreeSWITCH change, disabling it falls back on the next lookup, and installer re-runs never override the administrator's choice. Every stock-tier fallback writes one line to `/var/log/nginx/xml-stock-fallback.log`, so a silent degradation is visible. CDR ingestion always stays on PHP-FPM (never the worker). Measured on the 1 vCPU / 967 MB reference tier: the fast controller reaches 43 lookups/sec with 108 ms p50 latency and 92 %/100 % call completion at 5/8 calls/sec; the optional worker reaches 187 lookups/sec, ~14 ms p50 lookups and 84 ms p50 call setup at roughly 81 MB resident memory. `docs/operations.md` documents the option. **Upgrade note**: existing installs that re-run the installer keep their current worker state; to serve XML solely through the fast controller, run `sudo systemctl disable --now tallpbx-xml-worker`. No migration or `.env` change is required.
- **Slim Telephony Boot for the XML Worker and Fast Controller**: The persistent XML worker and the fast XML handler entry point now skip the administrative panel stack when their module providers boot — views, translations, migrations, panel routes, Livewire components, menus, permissions and console commands are never registered on the FreeSWITCH lookup and call detail record ingestion paths. Both renderers share one gate and one module list (`TelephonyWorkerProviders`), so their behavior cannot drift apart, and the administrative panel keeps the full stack exactly as before. The fast controller additionally drops the translation and Livewire service providers from its boot, trimming per-lookup startup work while producing byte-identical XML (verified by the fast-path and worker-parity byte-equality tests). This reduces the XML worker's memory footprint and the fast controller's per-lookup latency on constrained hosts. No migration, `.env`, or FreeSWITCH change is required.
- **Load-Test Harness Consolidated Under `load-testing/`**: The capacity-test documentation and scripts now live in one directory so any operator or AI agent can be pointed at it and reproduce a series. `load-testing/README.md` is the entry point, followed by `remote-setup.md` (every host setting with the command that proves it), `configurations.md` (each switch, its assertion, and its effect), `procedure.md` (the ordered run with checkpoints) and `reference.md` (flags, environment variables, artifact layout, JSON fields). The scripts moved to `load-testing/scripts/` and two previously unversioned tools (`cpuwatch.sh`, `ab-esl-reverb.sh`) are now committed. Raw results moved from the disposable `storage/app/load-tests/` directory to `load-testing/results/`, which is committed and survives deletion of the measurement hosts; the PBX keeps an ignored scratch copy. Reference paths in `docs/` and `AGENTS.md` point at the new directory.
- **Phase 4 Telephony Capacity Scaling (Production Logging Discipline)**: Switched the default FreeSWITCH logging level to `notice` across `config/freeswitch.php`, `.env`, and `.env.example`. Configured `scripts/resources/freeswitch.sh`, `/etc/freeswitch/autoload_configs/switch.conf.xml`, and `/etc/freeswitch/autoload_configs/logfile.conf.xml` to eliminate verbose `debug` formatting and disk I/O flushes during call bursts, reclaiming 15–20% CPU time while keeping vital call progress and error visibility intact. Preserves `debug` in `logfile.conf.xml` mapping so temporary diagnostics via `fsctl loglevel debug` or `FS_LOG_LEVEL=debug` work seamlessly. **Upgrade note**: existing servers should run `tpbx optimize:clear`, restart `freeswitch-listener` (`systemctl restart freeswitch-listener`), and execute `fs_cli -x "fsctl loglevel notice"` and `fs_cli -x "reloadxml"` to apply the production logging defaults.

The legacy `xml_cdr` migration is removed, and the module no longer ships the unused duplicate `XmlCdrService`. **Upgrade note**: run `tpbx migrate`, `tpbx module:sync --only-local`, and `tpbx db:seed --class=AdminSeeder`. Existing `xml_cdr` rows are not copied because the 5.x series requires a fresh install.
- **Call Detail Record CSV Export**: The call detail list can be downloaded as a CSV file, gated by a new `call-detail-records.export` permission so exporting is a deliberate grant rather than a side effect of being able to view the list — a CSV leaves the panel and lands on the operator's own disk, outside the tenant's access controls. The export contains exactly what the list shows: the same tenant scope and the same leg filter, read page by page so a large export never loads the table into memory, and capped at 25,000 rows with a notice when the cap is reached. ### Fixed
- **Call Detail Records Now Require a Call Reference Number**: The `cdrs` table no longer accepts a record without a call reference number. The `(call_uuid, leg)` pair is what stops a replayed record from being stored twice, and a database treats two blanks as two different values, so a blank reference number slipped past that unique key and the row could never be replayed safely. The column is now required, which moves the guarantee from "the ingestion code happens to be careful" to "the database enforces it for every writer". The ingestion parser already refused such a payload and quarantined it, so no behaviour changes and no call history is affected. **Upgrade note**: run `tpbx migrate`. The migration refuses to continue if any record already carries a blank reference number, because such a record can never be deduplicated and clearing it is an operator's decision; it never removes call history on its own.
- **FreeSWITCH Dashboard Active Call Refresh on Hangup & Periodic Keepalive**: Resolved a gap where active call counts on the dashboard failed to decrement when calls ended under the default essential ESL profile by registering `ChannelHangupComplete` in `BroadcastDashboardStatsOnFreeSwitchEvent`, and restored the 20-second `HEARTBEAT` keepalive to the essential event profile to preserve self-healing updates for wire:poll-free views.
- **FreeSWITCH Listen Command CLI Option Shadowing**: Removed the legacy closure wrapper in `routes/console.php` that shadowed `FreeSwitchListenCommand` in Artisan, restoring full option descriptions (`--once`, `--timeout`, `--buffer-size`, `--profile`, `--events`) on `--help`.
- **Cached Tenant Identity Can No Longer Outlive an Ownership Change**: The directory lookup caches the answer to "which tenant owns this username". That answer had a 60-second lifetime but no revision, so a SIP account or tenant domain moved to another tenant could keep resolving to the previous tenant until the entry expired. The identity key now embeds an identity epoch — the existing global routing revision — which `RoutingCacheObserver` bumps on every SIP account and tenant domain write (a missing epoch is a miss, never a default). Because the global revision also salts dialplan cache keys, a SIP account or domain edit invalidates each tenant's dialplan once on its next request.
- **Appliance Host Sync No Longer Empties Every Redis Database**: `appliance:sync-host`, which runs after a snapshot restore or an IP or hostname change, called `Redis::flushall()` and therefore wiped all logical databases at once — cache, sessions, and the CDR stream. Only the cache holds rendered routing XML that embeds the old address, and only the cache is safe to discard, so the command now flushes the telephony cache store alone. Signed-in administrators stay signed in, and no call records can be lost to a host sync.

### Removed
- **Lua XML Cache Proxy (Evaluated and Retired)**: The optional in-process FreeSWITCH Lua directory cache is removed from the product after measurement showed the trimmed fast controller and the optional Octane worker deliver comparable call capacity without a mirrored second representation of every rendered document. Removed: the `mod_lua` handler and its `lua.conf.xml` bindings template, the installer's Lua deployment step and `mod_lua` module ordering, the Laravel mirror (`FsXmlMirrorWriter` and the builder hooks), the `freeswitch.lua_proxy` config block, the `FS_LUA_PROXY_*`/`FS_REDIS_*` environment entries, and their test suites. The `freeswitch-mod-hiredis` package, its `hiredis.conf.xml` profile, and the opt-in `FS_HIREDIS_*` tenant-limit and last-call-marker dialplan actions remain in place unchanged. Its measurements remain under `load-testing/results/` and in `docs/load-testing-results.md`, the load-testing matrix drops the `v-lua-*` variants, and the design is recorded in `docs/architecture.md`. The code remains available in the repository history. **Upgrade note**: remove `FS_LUA_PROXY_*` and `FS_REDIS_*` lines from `.env`; delete `/etc/freeswitch/scripts/tallpbx_xml_handler.lua` and `/etc/freeswitch/autoload_configs/lua.conf.xml` if present, comment the `mod_lua` line in `modules.conf.xml`, keep `autoload_configs/hiredis.conf.xml`, and run `tpbx optimize:clear`.
